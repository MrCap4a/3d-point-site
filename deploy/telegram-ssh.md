# Telegram через европейский сервер

Подготовлено 12.11.2026. Боевой сайт пока использует старый образ и прямое
подключение. Из российского VPS Telegram Bot API недоступен; заявки сохраняются
в SQLite независимо от результата уведомления. Неуспешные уведомления автоматически
не переотправляются.

Включение: `TELEGRAM_TRANSPORT=ssh`. По умолчанию `direct` сохраняет прежнее поведение.
Каждый запрос открывает SSH к `TELEGRAM_SSH_HOST` (здесь `eu.aaal.ooo`), затем
TCP-канал только к `api.telegram.org:443`. HTTPS проверяет сертификат Telegram.
Общий лимит 10 секунд; соединения закрываются при успехе, ошибке и таймауте.
Matrix, Caddy и публичные порты не изменяются.

Обязательные SSH-настройки:

- `TELEGRAM_SSH_HOST`, `TELEGRAM_SSH_PORT` (по умолчанию 22), `TELEGRAM_SSH_USER`.
- `TELEGRAM_SSH_HOST_KEY_SHA256`: отпечаток доверенного публичного ключа сервера,
  стандартный формат OpenSSH SHA256. Проверку нельзя отключать.
- `TELEGRAM_SSH_PRIVATE_KEY_B64`: приватный ключ отдельного подключения в base64
  (это кодирование, не шифрование). Хранить только в SOPS/секретах окружения.
- Прежние `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` остаются теми же.

В репозитории infra подготовлены зашифрованные настройки и публичный установочный
скрипт. Приватный ключ не записывался в открытый файл и не выводился в журнал.
На EU нужно разрешить этот ключ пользователю `calom`. Принудительная команда
`/bin/false` запрещает выполнение команд этим ключом, `restrict` отключает терминал,
агента и X11; `permitopen` ограничивает исходящие SSH-каналы Telegram:443,
`from` разрешает подключение только с Beget 82.114.228.159. При переезде самого
Beget-сервера нужно обновить `from`. Не используем этот ключ для обратных туннелей.

Проверка после запуска нового образа (не отправляет сообщений):

```sh
docker exec print3d-print3d-1 node scripts/telegram-check.mjs
```

Вывод содержит только статусы `getMe`/`getChat`, без токенов, данных чата и заявок.
Проверку с реальной отправкой согласовать отдельно. Существующие помощники
`telegram:chat-id`/`telegram:test` используют прямое подключение и для проверки SSH
не подходят.

Локально: `node --test tests/telegram-transport.test.mjs`, `npm run lint`,
`npx prisma generate`, `npx next typegen`, `npx tsc --noEmit`.
CI также собирает Docker и проверяет сохранность данных после пересоздания.
Публикация образа разрешена только из master, отдельная ветка ничего не выкатывает.

Если завтра меняется только IP той же EU-машины, обновить A-запись `eu.aaal.ooo`.
SSH-ключ сервера остаётся прежним. При переустановке ОС/замене машины необходимо
сначала сверить новый ключ через доверенную консоль и обновить отпечаток в SOPS.

Справка по ограничениям ключей: https://man.openbsd.org/sshd.8#AUTHORIZED_KEYS_FILE_FORMAT
